## 项目经验

### 自主设计 Agent 框架与 AI 系统落地

**项目描述：** 在团队 AI 工程化能力空白的背景下，从 0 到 1 独立设计并落地了完整的 AI Agent 技术体系。针对营销助手这类多步骤有序任务场景，放弃开箱即用的 LangChain Agent 方案，自主设计了「规划 + 执行循环」的 Agent 工程架构，解决了纯 Agent 方案在流程确定性、步骤间数据传递上的不稳定问题，在生产环境持续稳定运行。

**项目职责：**

1. 设计声明式 Agent 能力注册表：每条能力项声明槽位（必填/可自动提取）、数据产出字段、依赖上游能力，注册表内容自动序列化为 LLM System Prompt，代码与提示词单一数据源，无需手动维护同步；扩展新能力只需在注册表添加一条记录，规划层和执行层零改动

2. 设计 Planner-Executor 两阶段架构中的规划层：单次 LLM 调用输出含步骤依赖关系和置信度评估的完整执行计划；置信度不足时由 LLM 自生成澄清话术追问用户，比硬编码问法更自然；规划阶段主动限制重试次数，避免流式 token 乱序到达导致前端状态机异常；规划过程的思考内容实时通过流式协议推送前端，减少多步任务的等待焦虑

3. 采用生成器协程（Generator）模型实现执行循环的暂停/恢复语义，支持两种暂停机制：进入步骤前的参数收集暂停和步骤内的交互确认暂停（结构化表单）；暂停时将执行中间态序列化到 Redis，恢复时从快照重建，跳过已完成的 LLM 推理阶段，节省 token 且避免识别结果漂移；步骤间通过显式数据链传递上游产出，不依赖 LLM 上下文记忆

4. 封装通用 LLM 结构化输出组件：三层 JSON 提取兜底（直接解析 → Markdown 代码块提取 → 正则提取）+ 将 Schema 验证错误详情注入重试 Prompt 的自纠错机制；并发安全设计，每次调用独立维护重试上下文，防止高并发下多请求互相污染错误信息；通过降级标记字段统计结构化输出失败率并接入可观测看板

5. 制定覆盖 Agent 执行全生命周期的 SSE 流式协议（8 种对称事件），通过 finally 语义保证每个 LLM 调用的开始/结束事件成对出现，多步 Agent 中任意步骤出错时前端流式状态机都能正常收尾；设计三层 LLM 封装（模型适配层 / 统一调用层 / 熔断层），双模型热备，熔断采用惰性状态转移（由下次请求触发而非定时轮询），故障切换对上层业务不可见

6. 建设三层可观测日志体系（接口级 / LLM 调用级 / Agent 步骤级），通过请求追踪 ID 与会话 ID 串联全链路；日志写入采用事件驱动异步模式，与 SSE 推流主流程解耦，日志失败不影响主链路；基于日志数据构建 AI 调用统计看板，支持成功率、错误分布、各步骤耗时、用户行为等多维实时统计

7. 将对话 UI、SSE 流式解析、多轮会话管理封装为内部 SDK，零 UI 框架依赖；业务接入只需两步：在管理平台配置系统提示词，在项目中实现消息发送回调完成业务编排，底层协议对接由 SDK 内部处理；多个业务团队通过该 SDK 快速落地 AI 对话能力，新业务接入成本从数周降至数天

### AI Agent 工具链与 MCP 生态建设

**项目描述：** 主导设计并落地 Skill Hub——一套 AI Agent 能力发布、发现、分发、安装的标准化平台，同时建设 CLI 工具和配套管理平台，形成从项目初始化到 AI 能力共享的完整闭环。这是公司第一套面向 AI Agent 的工具链基础设施。

**项目职责：**

1. 设计 Skill 三种形态：轻量知识片段 / 打包资源 / Agent 工作流型（声明式配置，携带完整 AI 工作环境）；工作流型 Skill 安装后能直接激活完整的 AI 协作模式，不只是文本内容

2. 实现声明式安装引擎：工具权限配置去重合并（保证多个 Skill 共存不覆盖）、配置文件幂等追加（重复安装不堆积内容）、MCP 自动注册；从架构上解决多 Skill 安装时相互覆盖的根本问题

3. 实现 MCP Server 集成，用户在 AI 编程工具对话框中通过自然语言触发 Skill 发现和安装，无需离开 IDE；遵循开放规范实现 Well-Known 发现协议，接入后官方工具可直接通过平台域名自动发现并安装 Skill；URL 使用相对路径设计，域名变更时索引无需修改

4. 设计 CLI 认证体系，API Token 与 Device Flow 两种模式互补：Token 只存哈希值并通过时序安全比较防止时序攻击，软撤销保留记录支持审计；Device Flow 引导用户在浏览器完成 SSO 授权，原子锁防止并发请求重复兑换凭证；Token 失效时内部自动触发重新授权，用户无感知

5. 设计 AI 安全扫描流水线：Skill 发布后异步触发扫描，按内容规模路由到不同精度的模型，LLM 输出结构化风险等级和发现项；不阻塞发布但标记高风险版本，管理平台展示审核状态

6. 实现软下架机制（借鉴 npm Yank）：版本记录保留并附加下架原因，被下架版本自动回退到上一个可用版本；结合条件请求增量更新和异步摘要计算，构成完整版本生命周期管理；文件传输通过重定向到对象存储，服务端不承担带宽

7. CLI 工具采用五层模块化架构；针对 Node.js 版本兼容问题实现多源检测、自动安装、进程重启后状态无损恢复；可观测性层全流程性能监控，上报失败写入本地队列自动补报，CLI 与平台双端脱敏确保用户隐私数据不落库

### Node.js 基础设施 npm 包体系建设

**项目描述：** 负责猫眼 Node.js 服务端架构设计与基础设施自建化。随着猫眼基础设施脱离美团内部平台自建化推进，从零设计并落地多个公司级 npm 包，覆盖 Redis、MySQL、SSO、RPC 调用四条核心链路，支撑了公司全部 Node.js 前端服务的后端调用。

**项目职责：**

1. 设计 Node.js 服务端基础设施分层架构：全局基础模块（数据库、LLM、日志、权限）与业务模块垂直内聚，模块间通过基础层协作而不直接依赖，新业务接入无需改动基础设施；全局请求处理管道（认证、数据转换、异常捕获等）通过依赖注入统一声明，支持路由粒度的豁免控制

2. MySQL 链路分三层设计：凭证层实现内存缓存 → 远程 KMS → 本地加密文件三级降级，KMS 故障不影响服务，明文凭证不落磁盘；连接层通过状态机与方法代理解决密码轮换和主从切换期间的连接重建问题，重建期间请求透明等待放行，旧连接上的事件监听器同步迁移

3. Redis 链路采用连接池与统一业务执行两层架构：连接池参数针对 Node.js 单进程模型调优（预热连接避免冷启动、空闲超时主动低于服务端阈值）；所有读写操作经由统一执行框架完成连接获取、超时竞争、结果归还的完整流程，超时后销毁而非归还连接，防止状态未知的连接被复用；同时适配历史 Hessian 编码协议，通过魔数字节识别区分字符串与序列化对象，保证与 Java 服务写入的历史数据互通

4. RPC 链路构建三层降级体系（服务网格 → 直连 → Thrift）：以滑动窗口成功率而非单次失败作为降级判断依据，避免网络抖动引发误判；Sidecar 多次离线后切换哨兵节点，通过 DNS TXT 记录动态发现；底层 Socket 连接通过请求 ID 多路复用并发请求，状态机解析 TCP 流完成粘包拆包

5. 设计并落地内部 SSO 认证 SDK，基于 OAuth 2.0 授权码流程：按请求类型分流认证处理，接口返回结构化错误、页面触发重定向；针对反向代理下 HTTPS 协议识别失效提供显式配置兜底；适配多种主流 Node.js 框架的中间件接入方式
